Design a minimally viable offline Windows desktop application for a Cybersecurity Tabletop Exercise Moderator.

The application will run on one Windows laptop connected to a projector or external monitor using Extended Desktop mode.

The laptop screen must display a private Moderator Console. The external monitor must display a separate Participant Display window. The participant display must never expose moderator-only information, unreleased injects, private notes, or upcoming events.

This is an offline-first application. During an exercise it must not require:
- Internet access
- A web server
- Cloud hosting
- User accounts
- External APIs
- Cloud databases
- CDN-hosted fonts or libraries
- Remote images, audio, analytics, or authentication

All scenario data, images, audio, exercise history, and hot wash responses must be stored locally on the Windows computer.

For the MVP, use a packaged desktop architecture suitable for Windows, preferably Electron with a local frontend and local file storage. Do not add a hosted backend. Use the simplest reliable local persistence approach, preferably versioned JSON files or SQLite only if necessary.

The MVP must support:
1. Moderator Console on the laptop display
2. Participant Display on the external monitor
3. Large count-up and count-down timers
4. Public information cards
5. Moderator-only information cards
6. Team-specific information cards that the moderator can read or deliver verbally
7. A planned information-release timeline
8. Editing unreleased information before release
9. Manual release, delay, skip, and replace controls
10. Random selection from prepared information pools
11. Large alarm, warning, X, and WRONG ASSUMPTION display effects
12. Team action and decision notes
13. Sequential hot wash entry for Teams 1–5
14. Local autosave and exercise recovery
15. Export of the exercise timeline and hot wash notes to a readable local report

Do not implement team devices, online collaboration, remote access, payments, cloud synchronization, AI-generated scenarios, or advanced scoring in the MVP.

Before writing implementation code, produce:
- Recommended application architecture
- Proposed technology choices
- Screen list
- Moderator workflow
- Participant display workflow
- Local data model
- MVP feature list
- Explicit list of features excluded from MVP
- Risks and Windows-specific testing considerations

Wait for approval before implementing.
